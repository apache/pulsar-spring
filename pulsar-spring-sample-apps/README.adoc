= Apache Pulsar support for Spring Sample Applications

Sample applications that can be used to demonstrate and manually verify Apache Pulsar support for Spring functionality.


[[build-apps]]
== Building
The sample applications are a separate Gradle build, which only shares the version catalog of the main build.

The main build includes it and substitutes its own projects for the Apache Pulsar support for Spring artifacts, so use this when developing.
Execute the following command from the root directory of the repository:
[source,bash]
----
./gradlew :pulsar-spring-sample-apps:build
----

Add `-PsampleTests` to also run the tests of the sample applications.

[[published-artifacts]]
=== Using published artifacts
When run on its own, the build gets the artifacts from a repository, as an application would.
The `pulsarSpringRepository` property sets the repository, as a path or a URL.
Without it, the build uses Maven Central and the Apache snapshot repository.

The following commands test the sample applications against artifacts published to a local repository:
[source,bash]
----
./gradlew publishAllPublicationsToLocalRepository
cd pulsar-spring-sample-apps
../gradlew runAllSampleTests -PsampleTests -PpulsarSpringRepository=../build/publications/repos
----

[[native-image]]
=== Testing the native image
The tests of `sample-native-image` start the application with ahead-of-time processing on the JVM.
The `nativeSmokeTest` task runs the same tests with the application as a native image, which requires GraalVM for JDK 25 in the `GRAALVM_HOME` or `JAVA_HOME` environment variable:
[source,bash]
----
../gradlew :sample-native-image:nativeSmokeTest -PpulsarSpringRepository=../build/publications/repos
----

[[run-apps]]
== Running

=== Pre-requisites
****
* The components have all been built by following the <<build-apps>> steps.
* Apache Pulsar standalone cluster  available at `pulsar://localhost:6650`

TIP: Some samples (those w/ a `compose.yaml` file) include Docker Compose support and will automatically start the Pulsar cluster. For the other sample apps you can start a standalone cluster locally by following the https://pulsar.apache.org/docs/next/getting-started-docker/[Pulsar Docker guide].
****

=== Steps

Make sure the above pre-requisites are satisfied.

===== IDE
To run the app in your IDE just choose `Run/Debug` on the desired sample application class.

===== Command Line
To run the app on the command line execute the following command from the root directory of the repository, using the name of the desired sample application:

[source,bash]
----
./gradlew :pulsar-spring-sample-apps:sample-pulsar-reader:bootRun
----

TIP: When running on the command line the build sets the JVM options that the Pulsar client and Netty need, as described in the https://pulsar.apache.org/pulsar-spring/reference/intro/system-requirements.html#pulsar-jvm-options[system requirements].
